# CodePet README 재구성 설계

## 목표

처음 방문한 일반 사용자가 CodePet의 용도, 지원 도구, 주요 기능, 실행 방법을 빠르게 이해하도록 README를 제품 소개 중심으로 재구성한다. 현재 코드에서 확인되는 기능만 설명하며 앱 동작이나 배포 방식은 변경하지 않는다.

## 시각 방향

- 기존 CodePet 캐릭터의 검은 머리, 흰 뿔, 귀여운 데스크톱 펫 인상을 유지한 전용 가로 배너를 사용한다.
- 배너는 어두운 데스크톱 작업 공간과 밝은 말풍선, 청록·파랑·보라 계열 상태 빛으로 작업 감시 기능을 표현한다.
- 이미지 안에는 생성형 텍스트, 공급자 로고, 워터마크를 넣지 않는다. 제품명과 설명은 선명한 Markdown 텍스트로 제공한다.
- 배너는 저장소 내부 `docs/assets/`에 보관해 외부 이미지 호스트에 의존하지 않는다.

## 문서 구조

1. 배너, 제품명, 한 줄 설명, 지원 플랫폼·런타임·테스트 배지
2. 핵심 가치: 네 공급자 동시 감시, 상태 말풍선, 계정별 사용량, 펫 커스터마이징
3. 빠른 시작과 패키지 빌드
4. 지원 대상과 데이터 처리 경계
5. 주요 기능 설명
6. 조작법
7. 커스텀 스프라이트 규격
8. 개발자용 코드 구조와 로컬 검증

긴 기술 설명은 `<details>`로 접어 일반 사용자의 첫 화면을 짧게 유지한다. 설치·실행 명령과 주의사항은 접지 않는다.

## 정확성 기준

- 지원 도구는 Codex, Google Antigravity, Claude Code, Kimi Code CLI로 표기한다.
- Kimi는 관리형 로그인에서만 `5h`·`7d` 남은 사용량을 표시하고 계정 전환 대상에서는 제외한다.
- macOS와 Windows 지원, npm 실행·빌드 명령, 로컬 로그 경로, 개인정보 표시 모드를 현재 구현과 맞춘다.
- 공식 배포 다운로드가 없는 상태에서 설치 파일을 제공한다고 오해할 문구나 배지는 사용하지 않는다.
- GitHub Actions가 비활성화된 저장소이므로 CI 통과 배지를 만들지 않는다. 테스트 배지는 로컬 `npm test` 명령을 가리키는 정적 설명만 사용한다.

## 검증

- README의 모든 상대 경로와 이미지 경로를 확인한다.
- `package.json` 스크립트와 README 명령이 일치하는지 확인한다.
- 지원 공급자, 사용량, 프라이버시, 스프라이트 규격을 관련 소스·테스트와 대조한다.
- `npm test`와 Markdown 링크 검사를 실행한다.

## 범위 밖

- 앱 UI, 기능, 버전, 배포 산출물 변경
- 공급자 공식 로고 사용
- 릴리스 생성 또는 PR 생성
