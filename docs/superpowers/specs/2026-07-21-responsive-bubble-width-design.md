# 반응형 말풍선 폭 설계

## 목표

CodePet 메시지와 활동 헤더가 현재 고정 폭 `270px` 때문에 과도하게 잘리지 않도록 말풍선 창 너비를 콘텐츠와 현재 디스플레이 크기에 맞춰 조절한다. 긴 콘텐츠가 창을 무한히 넓히거나 화면 밖으로 나가지 않도록 명확한 최소·최대 범위를 둔다.

## 검토한 방식

1. 고정 폭을 약 `400px`로 확대
   - 구현은 단순하지만 짧은 메시지에도 불필요하게 넓고 작은 화면 대응이 약하다.
2. 화면 비율만 사용
   - 구현은 간단하지만 콘텐츠 길이와 무관하게 폭이 바뀌고 디스플레이마다 체감이 불안정하다.
3. 콘텐츠 측정 후 화면 범위 안에서 제한
   - 짧은 메시지는 작게, 긴 제목과 배지가 있는 활동은 넓게 표시할 수 있다.
   - 사용자 승인에 따라 이 방식을 사용한다.

## 폭 규칙

- 최소 창 너비는 `300px`다.
- renderer는 현재 콘텐츠의 필요한 너비와 높이를 함께 main process에 보고한다.
- main process는 보고된 너비를 `300px` 이상, `520px` 이하로 제한한다.
- 현재 work area가 좁으면 최대 너비를 `workArea.width - 24px`로 더 제한해 좌우 `12px` 이상의 여백을 남긴다.
- 실제 상한은 `min(520px, workArea.width - 24px)`다.
- 잘못된 값, `NaN`, 음수, 비정상적으로 큰 값은 main process에서 무시하거나 제한한다.

## 콘텐츠 표시 규칙

- 일반 메시지 본문은 확보된 폭 안에서 자연스럽게 줄바꿈한다.
- 활동 제목은 한 줄을 유지하고 남는 공간이 부족할 때만 말줄임한다.
- 모델명과 추론 강도는 활동 제목에 포함된 현재 표시 계약을 유지한다.
- 상태 아이콘, 서브에이전트 배지, `5h`·`7d` 사용량 배지는 줄바꿈하지 않고 고정한다.
- 최대 폭에서도 너무 긴 본문은 기존 최대 높이와 세로 스크롤 계약을 유지한다.

## 창 크기와 위치 흐름

1. renderer가 말풍선 DOM을 갱신한다.
2. renderer가 측정한 `{ width, height }`를 기존 resize IPC로 보낸다.
3. main process가 현재 work area 기준으로 폭과 높이를 각각 제한한다.
4. main process는 제한된 실제 폭으로 pet 중심 위에 말풍선을 배치한다.
5. 좌우 화면 경계를 넘으면 work area 안으로 보정한다.
6. pet 위 공간이 부족하면 기존처럼 pet 아래로 이동한다.

창의 폭이 변경될 때도 pet 위치와 말풍선 중심 정렬을 다시 계산한다. 디스플레이 변경이나 화면 가장자리에서도 마지막 고정 폭을 가정하지 않는다.

## 구성 요소

- `src/bubble.js`
  - 렌더 완료 후 콘텐츠의 필요 너비와 높이를 측정한다.
  - 중복 resize 전송을 줄이기 위해 마지막 측정값과 같은 값은 다시 보내지 않는다.
- `src/bubble-preload.js`
  - resize IPC가 숫자 하나 대신 안전한 `{ width, height }` 객체를 전달한다.
- `src/main.js`
  - work area 기반 최소·최대 폭 제한과 실제 폭 상태를 관리한다.
  - BrowserWindow 생성, resize, 위치 계산에서 실제 폭을 사용한다.
- `src/bubble.css`
  - 본문 줄바꿈, 제목 말줄임, 고정 배지의 flex 계약을 유지한다.

## 호환성과 오류 처리

- 전환 중 구버전 renderer가 높이 숫자만 보내도 기존 높이 조절이 동작하도록 main process에서 호환 처리한다.
- 측정값이 유효하지 않으면 현재 창 폭을 유지한다.
- work area가 최소 폭보다 작은 극단적인 환경에서는 화면 여백 상한을 우선해 가능한 영역 안에 둔다.
- resize는 포커스를 가져오거나 숨겨진 말풍선을 임의로 표시하지 않는다.
- 자동 숨김, 클릭 동작, 개인정보 모드, provider 사용량, 작업별 메시지 상태에는 영향을 주지 않는다.

## 테스트와 검증

- 짧은 콘텐츠는 최소 폭 근처를 사용하고 긴 활동 헤더는 최대 `520px`까지 확장한다.
- 작은 work area에서는 `workArea.width - 24px`를 넘지 않는다.
- 잘못된 width/height 입력은 무시하거나 안전 범위로 제한한다.
- 위치 계산은 실제 반응형 폭으로 좌우 경계를 보정한다.
- 숫자 height만 보내는 기존 resize 계약이 유지된다.
- 제목은 말줄임되고 상태·서브에이전트·`5h`·`7d` 배지는 줄바꿈되지 않는다.
- 전체 테스트와 unsigned macOS 패키지를 다시 검증하고 일반 앱에서 짧은 메시지와 다중 활동 말풍선을 화면 확인한다.

## 범위 밖

- 사용자가 직접 말풍선 폭을 저장하는 설정
- 말풍선 드래그 또는 수동 리사이즈
- 폰트 크기나 최대 메시지 길이 정책 변경
- 말풍선 디자인·색상·애니메이션 재설계
